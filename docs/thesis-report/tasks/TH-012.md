## 2. Mục đích

Thiết kế chi tiết phân hệ khai thác tài liệu: pipeline xử lý tài liệu, truy hồi, xây dựng ngữ cảnh, sinh câu trả lời, trích dẫn, kiểm soát phạm vi.

## 4. Phạm vi không thực hiện

## 5. Điều kiện tiên quyết và phụ thuộc

## 6. Nguồn đầu vào

[docs/design/module-3-documents.md](../../design/module-3-documents.md), [docs/design/module-4-rag.md](../../design/module-4-rag.md); code `documents`, `rag`, `storage`, `llm` tại Report Baseline; prompt mẫu, cấu hình chunking/top-k/ngưỡng.

## 7. Công việc chi tiết

1. 2.7.1: sơ đồ kiến trúc phân hệ RAG (RAG Pipeline Diagram).
2. 2.7.2: các bước xử lý tài liệu (định dạng hỗ trợ, trích xuất, chunking — kích thước/chồng lấn thật, embedding — mô hình thật, lưu vector), trạng thái và xử lý lỗi.
3. 2.7.3: truy vấn → embedding → tìm kiếm (top-k, ngưỡng, lọc metadata).
4. 2.7.4: xây dựng ngữ cảnh, cấu trúc prompt (mô tả, không chép nguyên prompt dài), giới hạn token.
5. 2.7.5: cơ chế gắn và hiển thị trích dẫn nguồn.
6. 2.7.6: kiểm soát phạm vi truy xuất (chọn tài liệu, quyền truy cập tài liệu của người dùng).
7. Thông số nào chưa hiện thực → ghi là thiết kế; không tự đặt số.
8. Lưu file nguồn + ảnh xuất; W-STEP, TC-W.

## 8. Kết quả mong muốn
